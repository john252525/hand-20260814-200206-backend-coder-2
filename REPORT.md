# Итоговый отчёт — Тендерный конвейер (prototype-v3)

## Статус
Проект завершён в рамках Спринта 5. Все ключевые бизнес-процессы конвейера реализованы, покрыты тестами, система запускается и готова к демонстрации.

## Реализованные компоненты
- Каркас: FastAPI, SQLAlchemy async, PostgreSQL/pgvector, Redis, Celery, Docker
- Аутентификация: API-токены, rate limiting (Redis), идемпотентность
- Настройки: CRUD, сиды всех секций по ТЗ
- Категории: CRUD, bulk-import, эмбеддинги с fallback
- Тендеры: синхронизация с ГосПлан API, CRUD, фильтры, статистика, timeline
- Поставщики: поиск (Google + внутренний), дедупликация, приоритизация, привязка к лоту
- Коммуникации: SMTP/IMAP, шаблоны писем, Excel-вложения, классификация входящих
- КП: парсинг через LLM с fallback, расчёт маржи, покрытия
- Переговорный агент: уточнения, запрос скидок с ценами конкурентов
- Решения: approve/reject/request-info, оценка рисков, авто-рекомендация
- Вебхуки: CRUD, HMAC-подпись, отправка событий (ready_for_decision, cp.received, task.completed, decision.made)
- Метрики Prometheus: базовые счётчики из БД
- ML: сбор данных, обучение логистической регрессии с валидацией
- Файлы: upload/download/delete с валидацией entity_type/entity_id

## Финальные улучшения в итерации 4/4
1. **Уведомления вебхуков после commit** — в `tender_status_service` и `process_incoming` вызовы `notify_*` теперь происходят после фиксации транзакции основной бизнес-операции, исключая рассылку при откате.
2. **Retry вебхуков через Celery** — при неуспешной отправке создаётся фоновая задача с экспоненциальным backoff (1s, 2s, 4s, max 3 попытки), что повышает надёжность доставки.
3. **ML с валидационной выборкой** — при наличии более 20 наблюдений `train_test_split` (80/20), считается accuracy на тестовой выборке; при меньшем объёме — baseline.
4. **Полная документация** — обновлены README и этот отчёт.

## Команды для запуска
```bash
cp .env.example .env
docker-compose up -d postgres redis
cd backend
make migrate
make run
# В других терминалах:
make worker
make beat
```

## Демо-сценарий
1. Создать токен: `python -m app.cli.token_cli create --description "demo"`
2. Создать источник: `POST /api/v1/tender-sources`
3. Синхронизация: `POST /api/v1/tender-sources/{id}/sync`
4. Обработка: `POST /api/v1/tenders/{id}/reprocess`
5. Поиск/подтверждение поставщиков
6. Запрос КП: `POST /api/v1/tenders/{id}/request-cp`
7. Получение ответов через IMAP (автоматически)
8. Просмотр КП: `GET /api/v1/commercial-offers`
9. Переговоры: `POST /api/v1/negotiations/tenders/{id}/negotiate`
10. Решение: `POST /api/v1/decisions/{tender_id}/approve` или `/reject`
