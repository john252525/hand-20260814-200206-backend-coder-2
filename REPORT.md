# Итоговый отчёт — Тендерный конвейер (backend)

## Статус
Проект принят к демонстрации после финального ревью.

## Оценка готовности
- Функциональность по ТЗ: ~88% (осознанные упрощения описаны ниже).
- Стабильность: высокая, lazy-load ошибки устранены.
- Наблюдаемость: structlog в ключевых сервисах.
- Тесты: основные сценарии + новые эндпоинты.

## Ключевые ограничения (не блокеры)
- Полный автоматический цикл переговоров не реализован (управление через API).
- Реальные SMTP/IMAP требуют настройки; в демо используется заглушка (письма сохраняются в БД).
- Telegram/WhatsApp не интегрированы (только email).
- ML: логистическая регрессия вместо gradient boosting.

## Демо-сценарий
1. Создать токен
2. Создать источник
3. Синхронизация
4. Обработка тендера
5. Поиск и подтверждение поставщиков
6. Запрос КП
7. Получение ответов через IMAP или API
8. Просмотр КП
9. Переговоры
10. Решение

## Команды
```bash
cp .env.example .env
docker-compose up -d postgres redis
cd backend
make migrate
make run
make worker
make beat
```
